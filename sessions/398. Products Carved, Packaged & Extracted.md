## Front-loaded decisions

1. **§ 6.8 disposition: own vertical** (ratify at the gate — this is the block's headline ratification). The store passes the litmus test cleanly (a CRM-only or events-only install has no store), verticals never live inside a foundation plugin (Payments-adjacent would invert the dependency rule), and core-until-a-store-era contradicts the 385 reframe (the finish line is everything-a-package). Shape: `plugins/Products/`, namespace `Plugins\Products\`, provider `ProductsServiceProvider`, handle `products`, package `nonprofitcrm/products`, repo `crm-plugin--products`. Models/factories stay core (§ 6.7).
2. **Block shape: one session, three phases, fallback loud** (ratify): carve (incl. the inversion) → package + redraw + allocations drop → extract. If the carve or the inversion surfaces beyond the survey, stop honestly after carve or after carve + package — the D4 precedent says the inversion alone can fill a session.
3. **The third cross-repo inversion** (ratify): Payments v0.4.0 per survey item 6 — contract wording first, the webhook change in the plugin repo, tagged, core's lock bump + `^0.3` → `^0.4` widening in composer.json + distribution.json same-commit with the consuming listener. The listener owns the branch body verbatim (incl. find-or-create-contact); self-filter on `product_price_id` first.
4. **The dead `allocations` table drops** (ratify): the 396 posts precedent — guarded core drop migration (`Schema::dropIfExists`), dump regenerated, 348-precedent identity check, re-verify zero readers/zero rows before dropping. Its own commit.
5. **Both observers invert** (ratify): the two `#[ObservedBy]` attributes off `Product` and `Purchase`; `observe()` ×2 in plugin `boot()` (the 397 mechanics).
6. **The redraw is the sixth**: four tables, byte-faithful raw-DDL create-table migrations in FK order, **no sequences** (uuid PKs — the empty category recorded), the RESTRICT FKs travel as the behavior they are (the existing `CascadeDeleteTest` net rides unchanged), both identity checks ((a) full composition byte-identical; (b) products-absent boots + seeds + smokes clean — every public page 200, both POSTs 405 from the catch-all, zero product tables, widgets 39). Twin fixtures carry migrator paths **vendor-relative from birth** (the matured compression nuance).
7. **Composition-safety per survey item 9** — gate the five named reads on route presence; the recorded-debt class gates only what identity check (b) actually trips (the 383 fix-what-the-check-finds discipline).
8. **Tests:** rule-5 pass into a new `Products` phpunit testsuite; twins `ProductsRemovedTestCase` + `ProductsDisabledViaFlagTestCase` (with vendor-relative migrator paths); boundary guard `ProductsModuleBoundaryTest` (zero `Plugins\Products` in `app/`, zero allowlist, positive control); removal mirror proves both routes vanish (405 from the GET catch-all), both widget rows drop on sync (41 → 39), the admin surface vanishes, product data kept, no purchase activity logged on model-create (the observer detached), and the checkout dispatch has no listener (200, no purchase row — data kept).
