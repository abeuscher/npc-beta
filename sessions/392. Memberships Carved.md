## Front-loaded decisions (drafted at 391 close — review at prompt review; reopen only what the Open Gate flags)

1. **Shape:** `plugins/Memberships/`, namespace `Plugins\Memberships\`, provider `MembershipsServiceProvider`, handle `memberships`. `distribution.json` gains a `folder` entry (the honest source kind for a carve). The 388 empty-`plugins/` guard relaxations tolerate the refill by construction.
2. **`MemberResource` rides with the plugin** — it is the memberships admin surface over contacts (the DonorsPage precedent: contact-flavored, membership-subject). Its `Contact::isMember()` scope reach stays a core-model composition-debt item (recorded, not gated, until the package session's check).
3. **Models, factories, schema stay core this session** (§ 6.7; the squash redraw is the package session). The carve moves behavior: controller + route, observer, policy, the three admin resources + import pages, importer registries + mapper, both widgets, and the new inversion listeners.
4. **Surface 10 — invert both membership branches in one Payments release (v0.3.0).** The 389 pattern: the checkout-settled membership branch inverts to a `CheckoutSettled` listener plugin-side; the renewal branch to an `InvoiceSettled` listener (subscription ids disjoint across verticals; the listener self-filter rule is normative since 0.13.0). No `InvoicePaymentFailed` listener (membership failures were never handled — behavior preservation means not adding one). After this release the webhook's only remaining inline vertical branch is products (D8's freight).
5. **The portal seam stays core and unchanged this session** (survey item 7). Route name byte-identical from the plugin's route file; `SignupController`'s membership writes untouched. Composition-safety gating is package-session work; D5 owns any deeper inversion.
6. **PricingChart's scss asset re-points** `plugins/Memberships/Widgets/PricingChart/styles.scss` at the carve; `widgets:sync` + `build:public` + bundle-content proof (gate-4 discipline applies at every stage now).
7. **Testsuite:** new `Memberships` phpunit testsuite at `plugins/Memberships/tests/` (rule-5 membership rule; core keeps tests where memberships are fixture data), with `MembershipsRemovedTestCase` + `MembershipsDisabledViaFlagTestCase` twin fixtures — no migrator-path registration needed until the package session (schema stays core). Boundary guard `MembershipModuleBoundaryTest` (zero allowlist, the donations pattern).
8. **Block shape after the carve (decide at this session's close, not now):** Memberships is small enough that package + squash redraw + extraction may combine into one closing session (the D1 Payments compression, plus a two-table redraw) rather than the Donations block's two. Draft the next prompt(s) from what the carve actually surfaces.
9. **Contract doc at close: 0.15.0 → 0.16.0** — surface 10 gains the memberships slice (second cross-repo inversion, now a pattern); Package/External-repo sections unchanged; changelog.
