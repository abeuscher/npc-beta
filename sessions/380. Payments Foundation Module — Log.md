## Security considerations

The webhook surface moved unchanged: signature verification inside the controller, the `/webhooks/*` CSRF exemption stays core path-policy in `bootstrap/app.php`, no auth changes, no new endpoints. The two-Stripes client-billing boundary was untouched and both `ConventionDriftTest` bans remain green; the checkout-stays-up-under-admin-lock asymmetry (`EnforceSuspensionState`) was not modified. Cashier's removal deleted two unauthenticated vendor routes that were dead code — a small attack-surface reduction. The Random Data Generator's live-Stripe guard is behavior-identical with the plugin present; with the plugin absent it reads "not live" (no payments capability ⇒ generation allowed), a logged, deliberate default.

## P5 recommendation — Donations vs Events

**Recommended and owner-approved at close: Events.** (1) Events is the genuine showcase of the dependency rules — it consumes payments *optionally* and degrades to free events, the exact soft-dependency story the architecture sells; Donations without payments is an empty feature, so its degradation proof is trivial. (2) The events webhook inversion is one handler (pending-promotion + one queued mail) versus donations' three handlers plus subscription renewals — the cheapest first exercise of surface 10. (3) Events exercises more of the contract at once: an admin resource (surfaces 3/4 → PROVEN), seven widgets, an importer (surface 8), a scheduled command, a policy — the "whole contract" bar the plan sets for P5. The 381 prompts are drafted accordingly (survey ground-truthed at close; models/schema stay core by front-loaded decision).
