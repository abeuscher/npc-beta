**Manifest state:** `distribution.json` entry `{provider: Plugins\Payments\PaymentsServiceProvider, source: {type: folder, path: plugins/Payments}}` — no package, no constraint (the honest unpackaged shape; `DistributionManifestGuardTest` currently asserts the folder has **no** composer.json, so Phase 1's packaging must flip the manifest entry in the same commit or the guard fires — that's the guard working as designed).

## Front-loaded decisions (drafted at 386 close — review at prompt review; reopen only what the Open Gate flags)

1. **Names:** composer package `nonprofitcrm/payments`; repo `crm-plugin--payments` (the established `crm-plugin--{kebab-handle}` pattern; handle `payments` per `PluginServiceProvider::handleFor()`); first tag `v0.1.0`; require bound `^0.1`. Repo is **owner-created, public, empty** — the 385 rationale (credential-free `composer install` in every image-building context), confirmed at the Open Gate.
2. **Phase 1 is the full Stage B shape (P6 mechanics verbatim):** `plugins/Payments/composer.json` with explicit `version: 0.1.0` (the path-repo determinism device — dropped again at extraction, per the inversion rule), `type: library`, MIT, PSR-4 `Plugins\Payments\` → `""`; root path repository + `^0.1` require; lock committed same-commit; Dockerfile manifest COPY ×2 stages; `distribution.json` entry walks `folder` → `path` (gains `package` + `constraint` + the path source) and `plugins:manifest-sync` runs (provider-list no-op). No auto-discovery, ever.
3. **Phase 2 is the runbook, top to bottom:** copy to the sibling checkout, drop the `version` field, write the README (contract version 0.11.0, tags-are-releases, tests-stay-core), commit/tag/push; manifest `path` → `vcs`; composer repository swap + `composer update nonprofitcrm/payments`; `git rm -r plugins/Payments`; Dockerfile COPY lines removed; the three test file-reads re-pointed; all six verification gates (gate 4 recorded n/a — no assets).
4. **The package owns its dependency:** `nonprofitcrm/payments` requires `php ^8.2` + `stripe/stripe-php ^16.6`; root `composer.json` **drops** its direct `stripe/stripe-php` line in the same Phase 1 commit. The lock must resolve to the same stripe version (now transitive). This is the pattern every dependency-carrying plugin follows from here — record it in the contract's Package shape at close. (`PaymentModuleBoundaryTest` is unaffected: it bans SDK use in `app/`, not in the lock.)
5. **Tests stay core** (standing owner ruling, 384 close; Payments has no in-plugin suite to move — nothing forces the question this block; D11 owns the redistribution).
6. **Root PSR-4 stays** — Events is still in-repo, so `"Plugins\": "plugins/"` remains (the guard's accepted-overlap assertion is untouched; the mapping retires at D2-or-later when `plugins/` empties).
7. **Contract doc at close: 0.10.0 → 0.11.0.** Reference implementations (Payments = first extracted foundation plugin); Package shape gains the dependency posture (decision 4); External repo section confirmed against this run; runbook deltas folded (dependency-carrying manifest, no-assets gate wording, the manifest-first ordering this run exercises); changelog.
8. **No new third-party dependencies** (the stripe require *moves*; nothing is added).
