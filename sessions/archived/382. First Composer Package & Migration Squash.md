**Packaging state:** single monolithic `composer.json`; `"Plugins\\": "plugins/"` PSR-4 covers all three in-repo plugins; `config/plugins.php` (ordered provider list, loaded by `App\Providers\PluginServiceProvider`) is the sole activation + ordering authority. **Load-order facts that packaging must not disturb (proven load-bearing at 380/381):** `PluginServiceProvider` binds the three core registries *before* looping the plugin providers, whose `register()` populates them; plugin provider `boot()` runs before core's `routes/web.php` loads (at app booted), which is what keeps the Events plugin's GET `api/events.json` ahead of the page-slug catch-all (`EventsPluginSession381Test` pins this). Every vanish twin/mirror (`PaymentsRemovedTestCase`, `EventsRemovedTestCase`, SocketProbe, the pilot's removal test) keys on stripping/adding entries in `config('plugins')`.

**Docker/CI facts:** both Dockerfile stages run `composer install` from `composer.json` + `composer.lock` **before** `COPY . .` (layer caching) — a path repository pointing at `plugins/LogoGarden` fails those layers unless the package manifest is copied in first. CI (`tests.yml`) installs from a full checkout (unaffected). Deploy images are VERSION/SHA-immutable; no deploy this session.

## Front-loaded decisions (settled at 381 prompt-draft time — do not reopen in session)

1. **First package: LogoGarden, alone.** `plugins/LogoGarden/composer.json` — name `nonprofitcrm/logo-garden`, `"type": "library"`, PSR-4 `"Plugins\\LogoGarden\\": ""`, no dependencies beyond a PHP constraint (it programs against core's contract; composer-level core dependency modeling is P7+ territory). Root `composer.json` gains a `path` repository entry and requires `nonprofitcrm/logo-garden:*`. Payments and Events stay plain in-repo folders until P7 — one package is the mechanics proof; the vertical (with its schema and test interplay) is P7's.
2. **Activation and ordering stay with `config/plugins.php` — packages do NOT use Laravel auto-discovery.** The package declares no `extra.laravel.providers`. Rationale (the 381 P6 recommendation): the remove-the-line guarantee, the registry-before-plugins binding order, and the plugin-boot-before-core-routes ordering are all load-bearing and all keyed on the config list; composer auto-discovery would move activation to "edit composer.json + composer update" and surrender ordering to installation order. The config list is also the stated in-repo miniature of the future distribution manifest / per-install activation layer (P8). **This amends contract surface 1's Stage B sentence** ("replaces the config list with package auto-discovery") — record the amended posture in the contract doc at close: the provider stays the single entry point; the config list stays the activation authority through Stage B; auto-discovery is deliberately unused.
3. **Root PSR-4 overlap is accepted and documented.** `"Plugins\\": "plugins/"` stays in the root autoload (it covers Payments/Events); the package's own PSR-4 covers the same files — both mappings resolve identically, composer tolerates it, and the root mapping retires per-plugin as each becomes a package. One-line note in the contract doc's in-repo-shape section.
4. **Dockerfile fix shape:** copy the package manifest(s) before the composer-install layers (`COPY plugins/LogoGarden/composer.json plugins/LogoGarden/` in both stages, or an equivalent glob-safe form); the path-repo symlink created at install resolves fully once `COPY . .` lands. Keep the layer-caching property (source edits must not bust the dependency layer). Verify `composer install` + `dump-autoload` succeed in the image build — CI's image-building jobs are the signal; a local `docker build` to the composer layer is the fallback proof.
5. **The T1 squash, per the 348 precedent:** delete the three migration files, regenerate the dump (`php artisan schema:dump --prune` on a fully-migrated DB), bump the squash note in `docs/schema/README.md` (348 → 382), and run the identity check — `migrate:fresh --seed` clean, seeder-reproduced data phases spot-verified per the 348 log's procedure. The events tables remain in the dump (scope note above). Any test that references a deleted migration file by name is re-pointed or dropped per the 348 buffer precedent — expected: none (grep first).
6. **`composer.lock` is committed** with the path package pinned; `composer validate --strict` clean is part of the close gate. No dependency version drift beyond what the path package adds — this session adds no third-party packages.
