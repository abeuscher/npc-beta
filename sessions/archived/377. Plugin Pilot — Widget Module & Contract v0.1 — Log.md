## What was built

### Phase 1 — Extraction

- LogoGarden (both asset types — SCSS + JS + the `swiper` lib — so the asset seam was exercised end to end; the BarChart fallback was not needed) moved wholesale from `app/Widgets/LogoGarden/` to `plugins/LogoGarden/`: definition, demo seeder, template, `styles.scss`, `script.js`, thumbnails. Namespace `Plugins\LogoGarden\`, added to `composer.json` as the PSR-4 root `"Plugins\\": "plugins/"`.
- New `plugins/LogoGarden/LogoGardenServiceProvider.php` — registers the `plugin-logo-garden::` Blade namespace (pointed at the plugin folder) and the definition into the existing `WidgetRegistry`. The definition overrides `template()` to `@include('plugin-logo-garden::template')` and declares `plugins/LogoGarden/…` asset paths.
- New `config/plugins.php` — an ordered list of plugin provider class strings; new core `App\Providers\PluginServiceProvider` (in `bootstrap/providers.php` after `WidgetServiceProvider`) registers each at bootstrap. Remove the line = plugin gone; this list is the in-repo miniature of the future manifest/activation layer.
- `WidgetServiceProvider` lost its LogoGarden import + registration (40 core registrations remain).
- **Thumbnail-path seam (discovered, in-scope for behavior preservation):** three PHP sites plus `scripts/generate-thumbnails.js` hardcoded `app/Widgets/{Folder}/thumbnails`; without a fix the moved widget's picker thumbnail 404s. Added `WidgetDefinition::thumbnailDir()` (reflection on the concrete class's file location — correct for core and plugins with no override); `WidgetThumbnailController`, both `WidgetType` resolvers, and `WidgetThumbnailCoverageTest` now use it; the Node script writes to whichever of `app/Widgets/{Name}/` / `plugins/{Name}/` exists.
- Standing-guard coverage followed the move: the Alpine CSP guard (roots + globs), style-boundary, color-token, and inline-editing guards now scan `plugins/*` alongside `app/Widgets/*`, so the moved widget did not silently drop out of guard coverage.

### Phase 2 — Prove the seams

- `widgets:sync` idempotent with the plugin-registered definition (same row id across runs, one row, 41 definitions synced); row carries the plugin template include + plugin asset paths.
- `build:public` green; the served manifest + bundles verified to carry LogoGarden's SCSS/JS from the plugin path (load-bearing check — `collectSources()` silently skips missing files).
- New `tests/Feature/PluginPilotSession377Test.php` (5 tests): registration via the config list + provider loaded; the plugin provider alone populates a fresh registry; core provider source no longer references the pilot; view namespace resolves (and `widgets::LogoGarden.template` no longer does); synced row shape + every declared asset path exists on disk.
- Render parity: `LogoGardenContractRetrofitTest` / `LogoGardenWidgetTest` (imports/seeder class updated to `Plugins\LogoGarden\…`) stay green through the contract resolver.
- Two stragglers the initial sweep missed, caught by the full suite: `AppearanceConfigRenameTest` (literal template path) and `WidgetThumbnailCoverageTest` (path built via a local helper, replaced by `thumbnailDir()`).
