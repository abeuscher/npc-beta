## Production deployment notes

An **existing** deployed database has the four donation tables but not the four new migration rows, so a plain `migrate` would try to re-create existing tables and fail. One-time step per environment (the 383 squash-class precedent):

- **Disposable data** (demo droplet, auto-deploy server): `docker exec nonprofitcrm_app php artisan migrate:fresh --seed --force`.
- **Data must be kept:** mark the four plugin migrations as applied without running them, then `migrate` behaves normally:

  ```
  docker exec nonprofitcrm_postgres psql -U postgres -d <db> -c \
  "INSERT INTO migrations (migration, batch) SELECT unnest(ARRAY[
     '2026_08_19_000001_create_funds_table',
     '2026_08_19_000002_create_donations_table',
     '2026_08_19_000003_create_donation_credits_table',
     '2026_08_19_000004_create_donation_receipts_table']),
     (SELECT coalesce(max(batch),0)+1 FROM migrations);"
  ```

Fresh installs need nothing special — dump → plugin migrations → seeders is the normal path. The deploy image requires the Donations manifest COPY lines (in this branch's Dockerfile). VERSION bumped 0.389.01 → **0.390.01**.
