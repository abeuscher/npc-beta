## Process rules for every session

Base-prompt process rules apply in full (see `sessions/template-base-prompt.md`). Session-specific:

- **No-flag behavior preservation is total.** With `PLUGINS_DISABLED` unset or empty, every route (272/272), test total, guard, and visual surface is byte-identical to the 383 close. The new behavior exists only behind the flag.
- **The config list stays sacred — the flag only filters, never reorders and never adds.** `config/plugins.php` remains the installed superset and the sole ordering authority; the disabled set is subtraction only. Every existing strip-the-line test passes with its assertion content unchanged.
- **Runtime-disabled ≡ strip-the-line.** The removal mirrors are the executable spec: the flag mechanism must produce exactly the state `EventsRemovedTestCase`/`PaymentsRemovedTestCase` assert (no registration, no routes, no schedule, no widget rows on sync, data kept, other plugins untouched). If the mechanism you build cannot reproduce that equivalence, stop and surface it — that is a genuine design fork.
- **Disabled = inert, never destructive** (normative rule 4) binds mechanically: disabling stops the provider from registering — nothing may delete, migrate-down, or mutate plugin data or schema. The enable-later path (flag removed → restart → `migrate` runs pending plugin migrations) is a verified run this session, not an inferred behavior.
- **Fail loudly on operator error.** An unknown handle in the disabled set is a misconfiguration whose silent acceptance would leave a plugin running that the operator meant to disable — the front-loaded decision makes this a bootstrap failure; do not soften it to a log line (security-over-usability).
- **Scope is binding.** No FM surface (no health-payload plugin manifest — § 4d defers it explicitly), no admin toggle UI, no DB-backed activation store, no distribution manifest (P10), no Payments packaging, no per-plugin npm workspace work. Discovered adjacent work → housekeeping inbox or the plan doc's backlog, one line, move on.
