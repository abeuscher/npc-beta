# 396. Blog Carved, Packaged & Extracted

The D6 block runs start to finish in one session: the Blog behavioral surface — `PostController` + the two `blog_prefix` routes, the BlogListing and BlogPager widgets, and the Post admin resource — carves into `plugins/Blog/`, packages as `nonprofitcrm/blog`, and extracts to `crm-plugin--blog` in the seventh runbook run. **There is no squash-boundary redraw**: the survey (below) found the blog owns no live tables — posts are `Page` rows of type `post` (the Post admin resource's `$model` is `Page`), and the `posts` table in the core dump is dead schema with zero readers and zero rows. The block's design freight is the **BlogPager cross-plugin asset input** (the `crm-plugin--events` EventsListing declaration) and the **dead-table disposition**.

## The survey (ground truth, captured at 395 close from live code)

**The blog surface today (all core):**

1. **Posts are Pages.** There is no `Post` model. `PostController` (`app/Http/Controllers/PostController.php`) renders `Page` rows: `index` fetches the page whose slug is the `blog_prefix` setting ('news'), `show` fetches `Page` type `post` by prefixed slug — both through the same `PageBlockRenderer` path the catch-all uses. `PostResource` (`app/Filament/Resources/PostResource.php` + four pages: `ListPosts`, `CreatePost`, `EditPost`, `EditPostDetails`) declares `$model = Page::class` with `HasPageBuilderForm` — the MemberResource-on-Contact precedent (a plugin resource over a core model is proven, session 392).
2. **The `posts` table is dead schema.** `CREATE TABLE public.posts` sits in the dump (uuid PK — no sequence; one FK `author_id → users ON DELETE SET NULL`; unique slug; author index) with **zero readers** (every "posts" reference in `app/` is `Page`-typed — verified by grep) and **zero rows** in the dev database. It predates the pages-as-posts CMS shape. Disposition: decision 3.
3. **Routes, two:** `posts.index` (GET `/{blog_prefix}`) and `posts.show` (GET `/{blog_prefix}/{slug}`) at `routes/web.php` ~39–41, ahead of the catch-all — they move to the plugin route file registered at provider `boot()` (the proven ordering), names/URIs byte-identical. No auth, no throttles, no middleware beyond `web`.
4. **Widgets, two:** `BlogListing` (assets: `script.js` + `styles.scss`; contract `SOURCE_SYSTEM_MODEL` model `post`) and `BlogPager` (asset: `styles.scss`; same model; its template reads `$pageContext->currentPage->type === 'post'`). Thumbnails travel. **The cross-input (the design freight):** `crm-plugin--events`' EventsListing declares core `app/Widgets/BlogPager/styles.scss` as its second SCSS build input (surface 11's recorded cross-plugin case) — if BlogPager travels, that path dangles and `collectSources()` **silently drops it** from the bundle. Decision 2 resolves this.
5. **The `post` page type is core CMS-engine vocabulary and stays core** (the type is to Page what `member` was at 394 — engine, not vertical): `PageObserver`'s type-flip slug-prefixing, `CmsFormFields`' slug-prefix UI, `PageBuilder`'s type handling, `GeneralSettingsPage`'s `blog_prefix`-rename re-slugging, `NavigationMenuResource`'s post-page listing, `TagResource`/`WidgetTypeResource` labels, `LlmsTxtController`'s type exclusion, `RandomDataGenerator`'s scrub-posts + seeded `blog_pager` widgets. All are `Page`-model reads — **composition-safe by construction** (no plugin table, no guard); none needs a gate to avoid a crash. Verify at session; untripped candidates are not debt, they are simply core.
6. **`blog_prefix` plumbing stays core:** the `AppServiceProvider` site-setting bridge (`site.blog_prefix`), the setting itself, and every consumer in item 5. The moving `PostController` reads `config('site.blog_prefix')` — a core config read, legal from plugin code.
7. **Topology:** `BasePageSeeder` seeds the blog index page (slug = `blog_prefix`, type `default`, one `blog_listing` widget) + the News nav item. Blog-absent: the page still seeds and **still renders via the catch-all** (type `default` — `seedWidget` skips the missing widget type, so it seeds empty; `/news` answers 200 either way, just without a listing). `TemplateSeeder` seeds a template carrying a `blog_pager` handle entry — verify its missing-type behavior at session. Whether to gate the blog-page/nav seeding is a **topology judgment, not a crash fix** — decision 4.
8. **Permissions:** `PermissionSeeder`'s `$fullPermissions('post')` grants stay core-seeded (the 381 extracted-vertical nuance — the plugin declares no permission names).
9. **No mailables, no email-template handles, no observers** (PageObserver is core, item 5), **no scheduled commands, no importer, no policy** (Page policy is core), **no capability consumers** — no sibling depends on blog presence.
10. **Tests (rule-5 pass at session):** blog-subject candidates — `BlogListingContractRetrofitTest`, `BlogPagerContractRetrofitTest`, `BlogPagerEndToEndTest`. Stay-core candidates (blog rows as fixture data / core engine subjects): `ContentListingWidgetsTest` (multi-widget engine parity — it also reads events templates from the vendor path), `AppearanceConfigRenameTest`, `BuilderPublicRenderParityTest`, `WidgetTokenNamespaceTest`, `DateFormatHintsTest`. Direct file reads to re-point: survey at session with the runbook's step-0 greps (ContentListingWidgetsTest's template reads are the likeliest).

## Front-loaded decisions

1. **Block shape: one session, three phases** (carve → package → extract), no redraw phase — ratified at the open gate. Fallback: stop after carve + package if the carve surfaces beyond the survey.
2. **The BlogPager cross-input resolves by lifting the shared pager styles into core** (**ratified by the owner at the 395 close and recorded as ADR 0007** — shared front-end dependencies are core-owned; exceptions are explicit, recorded departures). The pager rules EventsListing consumes move to a core-owned shared stylesheet (e.g. `resources/scss/widgets/_shared-pager.scss` or the widget-shared convention the session finds cleanest); BlogPager's definition declares the core path + its own remainder; a `crm-plugin--events` **v0.1.3 rider** re-points EventsListing's second SCSS input to the core path (the 389/394 rider mechanics — contract wording → sibling edit → tag → core lock bump same-commit, `^0.1` unchanged). This dissolves the cross-plugin coupling instead of chaining it: the alternative (Events declaring the *blog plugin's* vendor path) would silently drop pager styles on every blog-absent composition — exactly the surface-11 caveat. Gate 4 proves the pager rules in the bundle from **both** declarations.
3. **The dead `posts` table drops** (recommended; owner ratifies at the gate — it is a real schema change). A core migration drops the table (guarded `DROP TABLE IF EXISTS`), the dump regenerates without it (the 382/T1 absorbed-squash mechanics, 348-precedent identity check — the diff must be exactly the posts DDL), and `docs/schema/posts.md` is removed with a README note. It is not plugin freight — no reader exists to carve; leaving it would only defer the same drop to D12's core-slimming audit. If declined: one line in the housekeeping inbox, move on.
4. **Topology stays unGated** (recommended): the blog index page is a type-`default` page that renders on every composition; blog-absent it is an empty News page, not a 404 shell — no seeder gate, no capability, no `Route::has` gate unless the identity-check smoke trips something real. **No `blog` capability ships** — nothing consumes blog presence (survey item 9); the presence signal, if a gate is ever forced, is route presence (`Route::has('posts.index')` — the memberships precedent).
5. **Shape:** `plugins/Blog/`, namespace `Plugins\Blog\`, provider `BlogServiceProvider`, handle `blog`, package `nonprofitcrm/blog`, repo `crm-plugin--blog`. Widgets nest under `Widgets/`; `PostController` → `Plugins\Blog\Http\Controllers\`; the two routes to the plugin route file at `boot()`. Manifest entry appended last, `folder` → `path` → `vcs` in-session (the source-kind walk). P6 package mechanics verbatim; the runbook end-to-end for the extraction (version field dropped, asset declarations vendor-relative, README on the member-portal model, tag `v0.1.0`, core swap + `git rm` + lock pin + Dockerfile COPY-line add-then-remove, phpunit `Blog` testsuite → the vendor path at extraction).
6. **Tests:** rule-5 membership pass into a new `Blog` phpunit testsuite; twin fixtures `BlogRemovedTestCase` + `BlogDisabledViaFlagTestCase` (**no migrator path, permanently** — the plugin owns no schema; note the fixtures' docblocks say so explicitly rather than carrying an expiring caveat); boundary guard `BlogModuleBoundaryTest` (zero `Plugins\Blog\` in `app/`, zero allowlist, positive control); removal mirror proves the two routes vanish to the catch-all (`/news` still 200 as the seeded default page — the assertion is listing-absent, not page-absent) and `widgets:sync` drops the two widget rows.
7. **Contract doc at close: 0.19.0 → 0.20.0** — Package shape seventh consumer; External repo seventh consumer; surface 11's cross-input case updated (the Events declaration re-pointed core-side, the rider recorded); surface 5 note: the first vertical extraction with **no owned schema** (the empty redraw category recorded, the no-migrator-path fixtures); changelog. Plan doc D6 ✅; the D7 kickoff survey (Forms — `WebForm` + submissions) captured at close; 397 prompts drafted.
