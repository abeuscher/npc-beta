## What was built

Emergent session, not a launch-schedule position: at the 374 close the owner
re-set priorities — outreach has ended and the codebase is now a portfolio
piece whose technical quality is the point. The one defect named as
disqualifying for a reviewer was that every public page of the production site
popped console errors. The fix was mandated to be the *correct* one: the
enforced public Content-Security-Policy stays exactly as hard as session 370
(Security S1) left it, and the front end moves to fit it.

### Phase 1 — Diagnosis confirmed, and the CSP-build constraints established empirically

- **Production baseline re-confirmed before touching anything:** 32 issues
  across 8 sampled pages — 4 on every page, all Alpine-under-CSP — matching the
  374 recon exactly. Reproduced locally (identical 4 per page on every page that
  exists locally; `/docs` is a production-only page and 404s on the dev stack).
- **The session prompt's central assumption about `@alpinejs/csp` was wrong, in
  our favour, and was corrected before any template was edited.** The prompt
  expected a path-only evaluator — "no inline object literals, no inline
  statements, no comparisons in bindings" — which would have implied rewriting
  every widget. A standalone spike (a scratch page served with the byte-identical
  production CSP header) showed the build ships a real JavaScript-subset parser.
  The spike included a **control**: `new Function()` and `eval()` both threw
  `EvalError`, proving the policy was genuinely enforcing and the permissive
  results were not an artefact of an unapplied header. Run against 3.15.11, then
  **re-verified against 3.16.2**, the version npm actually resolved and shipped.
- **Works unchanged** (so it stayed unchanged): inline data-only `x-data`
  objects including nested objects, arrays and deep paths; assignments in
  handlers; comparisons, ternaries, negation and `&&` in bindings; method calls
  with literal arguments; getters; `$store` / `$el` / `$refs` / `$nextTick`;
  `x-for` with `:key`; `x-model` and its modifiers; `x-transition`; every event
  modifier; and a registered component invoked with an object argument.
- **Breaks — exactly four shapes:** method definitions inside an inline
  `x-data`; arrow functions anywhere in a directive; `if` statements and
  multi-statement handlers; optional chaining and any reference to a `window`
  global. `x-html` is refused outright by the build.
- **Failures are loud** — a console warning *and* an uncaught page error — which
  is what makes a browser-side console assertion a genuine regression net rather
  than a snapshot.

### Phase 2 — The migration (iteration /1)

- `resources/js/public.js` imports `@alpinejs/csp` instead of `alpinejs`.
- **New shared registration bridge**, `resources/js/shared/widget-components.js`:
  registers every `window.NPWidgets.*` factory as an `Alpine.data()` component.
  The registry is read *inside* the `alpine:init` handler, so bundle and script
  ordering are irrelevant. **Both surfaces call it** — `public.js` and
  `admin.js` — because the page-builder preview renders the same widget
  templates against Filament's Alpine, and the widget bundle already loads
  there. This was the integration seam most likely to break silently.
- **Twelve widgets migrated.** Four already kept their JS in
  `app/Widgets/{Name}/script.js` and only needed the template to name the
  component instead of calling a global (BarChart, EventMiniCalendar), two of
  those also moving an `x-effect` guard into a method (BlogListing,
  EventsListing). Eight had their JS lifted out of the template into a new
  `script.js`, with Blade-computed settings passed through a JSON config block —
  the `x-ref` + `application/json` convention BlogListing and EventsListing
  already used (Nav, Carousel, ProductCarousel, LogoGarden, DonationForm,
  PortalSignup, SocialSharing, RandomDataGenerator).
- **Nav's session-334 keyboard behaviour is reproduced exactly**, not
  approximated: arrow-down opens a dropdown and moves focus to its first menu
  item; escape inside a dropdown closes everything and returns focus; escape
  anywhere on the page closes everything. Handlers that need the element the
  listener sits on take `$event` and read `currentTarget` — inside a component
  method `this.$el` is the component root, not the directive's element.
- **Shared components:** `custom-select` and `radio-group` both moved off
  Blade's `@js()`, which compiles to `JSON.parse(…)` — a global the CSP build
  cannot reach from a template expression. custom-select's config moved to the
  same JSON config block; radio-group emits escaped single-quoted literals.
- **Left untouched because already compatible:** MapEmbed, SetupChecklist,
  site-header, and the site-footer theme toggle.
- **Two incidental defects found and fixed.** (a) `radio-group`, used by the
  public form component, was broken the same way and **would have shipped
  broken** — the static guard caught it, not the page audits, because no audited
  page happened to place it. (b) The Nav demo seeder never applied its fixed
  `MENU_ID`: `id` is not in `NavigationMenu::$fillable`, so `updateOrCreate()`
  dropped it and `HasUuids` generated a random key that `demoConfig()` could
  never find. The demo nav also gained child items, so the widget's one piece of
  real interactivity is now actually exercised (dropdowns are hidden until
  opened, so widget thumbnails are unaffected).

### Phase 3 — Standing guards and verification (iteration /1)

- **`tests/Feature/PublicAlpineCspGuardTest.php`** — the static half. Needs no
  browser and no built bundle, so it runs in every environment including CI. It
  bans the four shapes plus `x-html` and window-global reads in public-surface
  Alpine attributes, and asserts that every component a template names is
  actually registered by some widget script. Admin-only Blade is excluded by an
  explicit, documented list rather than by directory: scanning is **opt-out by
  design**, so a newly added public component is covered by default.
- **`tests/e2e/public-console-errors.spec.ts`** — the browser half. Asserts both
  halves of "fixed": the pages emit nothing, **and** the components respond —
  theme store toggles, nav dropdown opens on keyboard with focus landing in the
  menu and escape closing it, custom select opens/filters/selects, donation form
  tracks amount selection, copy-link confirms. A console-only check would still
  pass on a page rendering inert widgets, which is the failure mode this session
  existed to fix. The spec skips itself where the widget bundle is unbuilt — the
  isolated e2e stack has no build server, the same recorded constraint
  `widget-color-tokens.spec.ts` already documents.
- **Four existing tests updated** because they asserted the pre-migration
  implementation rather than behaviour: two LogoGarden tests read Swiper's inline
  `spaceBetween` (now `"gap"` in the JSON config block), SocialSharing asserted
  the inline clipboard handler (now a named component + method). The nav registry
  test compared `assets` with `toBe` — order-sensitive — against a Postgres
  `jsonb` column that normalises key order; it had only ever passed because nav
  carried a single key, so adding a second one exposed it. `toEqual` is the
  correct comparison.
- **Local verification: 0 issues across 24 pages** — every marketing page,
  `/events`, `/news`, a blog post, an event page, portal signup, and each of the
  twelve migrated widgets individually through the `/dev/widgets/{handle}` demo
  harness (which renders widgets with demo data, so the six placed on no page
  were still exercised).
- **The one failing page-builder e2e spec was proven pre-existing, not
  inherited on faith:** `table-widget.spec.ts` (a ProseMirror cell-merge
  assertion) fails identically after rebuilding with the pre-change JS restored
  from `main`. Left as-is — not this session's surface.
- `alpinejs` removed from `package.json`; `public.js` was its only importer and
  `@alpinejs/csp` carries its own reactivity dependency.

## Security considerations

This session is a security-posture session wearing a bug-fix hat: the entire
point was to change the front end to fit the policy rather than relax the policy
to fit the front end. The `'unsafe-eval'` carve-out was considered and rejected
by the owner by name.

`app/Http/Middleware/SecurityHeaders.php` and `config/security.php` were **not
edited at all** — the public `script-src` is byte-for-byte what S1 shipped, and
the admin-only `'unsafe-eval'` carve-out Filament requires is untouched. The S1
header tests stayed green without modification, which is the evidence the change
stayed out of the policy layer entirely. The migration removes eval-shaped
expression evaluation from the public bundle outright, so the enforced policy
now governs a front end that provably runs under it.

The finding worth carrying forward, recorded in the security-hardening track
doc: **S1's control was correct but unverified.** The public CSP was enforced
and the header tests passed, yet every Alpine component on the public surface
was dead in production for four sessions and the only outward sign was console
noise nobody read. A header-level control is not proven until something
exercises the surface it governs in a real browser. Both new guards exist to
make that permanent for this class.

## Production deployment notes

**None beyond standard `migrate`** — but one ordering dependency is worth
recording because it silently bit this session mid-work.

Widget asset paths are read from the `widget_types.assets` **database column**,
not from the definition classes, so `build:public` on its own will happily
produce a bundle omitting every newly declared `script.js` — leaving the widgets
dead in exactly the way this session set out to fix. `php artisan widgets:sync`
must run first. `.github/workflows/deploy.yml` already does this in the right
order (sync at line 119, build at line 124), which is why the production deploy
came out clean with no manual intervention. The trap is local rebuilds, not the
pipeline.

The Nav demo seeder change is dev/thumbnail-only and needs no production run.

## Deferred decisions

- **Admin-panel CSP stays Report-Only with its `'unsafe-eval'` carve-out** —
  deliberately untouched. Enforcing it remains the open S1 residual, and would
  require this same migration across Filament, Livewire and their Alpine usage,
  which is vendor surface rather than ours.
- **The `table-widget` page-builder e2e failure** (ProseMirror cell merge) is
  pre-existing on `main` and left in place; it belongs to whoever next touches
  the table widget, not to this session.
- **The four-shape constraint is now load-bearing knowledge** for anyone adding
  a public widget. It is documented in the guard test's docblock and enforced by
  that test, rather than in a separate document that would drift.
- **Roadmap reconciliation is session 376's**, per the 374 owner ruling — the
  launch schedule stays suspended, not resolved, and this session did not touch
  `release-plan.md`.
