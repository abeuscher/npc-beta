## Front-loaded decisions (drafted at 388 close — review at prompt review; reopen only what the Open Gate flags)

1. **Shape:** `plugins/Donations/`, namespace `Plugins\Donations\`, provider `DonationsServiceProvider`, handle `donations`. `distribution.json` gains a `folder` entry (the honest source kind for a carve; packaging flips it to `path` next session). The empty-`plugins/` guard relaxations from 388 need no revert — they tolerate a non-empty set by construction.
2. **Models, factories, schema stay core this session** (§ 6.7 precedent; the squash redraw is the package session). The carve moves *behavior*: controller + route, observers, policies, mailables, admin pages, importer registries, the two widgets, the listener(s).
3. **Surface 7 — build the registry, move the two donation handles.** A core `EmailTemplateRegistry` (the `ImporterRegistry`/`CapabilityRegistry` pattern: core singleton, plugins contribute handle → defaults at `register()`), `EmailTemplate::defaults()` falling back to it for handles the core array doesn't carry. The two donation handles move into the plugin's contribution. **Core-owned handles stay in the core array** (`portal_password_reset`, `admin_invitation`, `form_submission`, `portal_form_collision`). **The three events handles also stay in core's array for now** — moving them is a `crm-plugin--events` release, out of this session's scope (backlog line: Events adopts the registry at its next natural release).
4. **Surface 10 — invert the checkout-settled donation branch this session; decide the recurring branches at the Open Gate.** The drafted posture: the Payments webhook's `donation_id` branch inverts to the `CheckoutSettled` dispatch (the events precedent exactly — the Donations listener owns promotion, transaction recording, acknowledgment); the **recurring/invoice branches invert in the same release** (a second core event, e.g. `InvoiceSettled`, dispatched with the invoice + metadata; the Donations listener owns the subscription-donation lookup) so Payments ships **one** release with no `Donation` model reads left. This is the expensive-to-reverse contract-surface change — pause at the gate if the one-release-or-two split reads differently.
5. **The Payments release mechanics (first post-extraction plugin release):** contract-first — the surface-10 wording lands in `docs/plugin-contract.md`, the webhook change lands in `crm-plugin--payments` (sibling checkout), tagged **`v0.2.0`** (behavior change, minor bump), core's lock bumped via `composer update nonprofitcrm/payments` in the same commit as the listener that consumes it. The `^0.1` require needs widening to `^0.2` — with `distribution.json`'s constraint updated in the same commit (the guard enforces agreement).
6. **Surface 9 — scope to what the carve actually forces.** The normative rule (relations on `contact_id`, plugin-owned tables) is already the donations shape. The admin-socket half (a plugin contributing a contact-screen panel) is **not** built this session unless the carve strands an existing contact-screen surface; `ContactResource`'s donation reads are composition-safety items for the package session's identity check, not carve blockers. Surface 9 promotion happens when the socket is genuinely exercised — honesty rule over ambition.
7. **Routes preserved byte-identically** (names/URIs/middleware), route count 272/272; the checkout POST registers from the plugin's route file ahead of the catch-all (the events ordering precedent).
8. **Testsuite:** new `Donations` phpunit testsuite at `plugins/Donations/tests/` (rule-5 membership: subject tests move; core keeps tests where donations are fixture data), with the removal/flag twin fixtures (`DonationsRemovedTestCase` pattern) proving the vanish semantics — schema stays core this session, so the fixtures need **no** migrator path registration until the package session.
9. **Contract doc at close: 0.12.0 → 0.13.0** — surface 7 PROVEN (registry + first plugin contributor), surface 10's donation slice PROVEN + the cross-repo inversion pattern recorded (what a post-extraction branch inversion costs), the Payments release noted in External repo, changelog.
