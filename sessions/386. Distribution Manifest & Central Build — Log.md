### Phase 1 — The manifest + generation + guards (`92a07408`)

- **`distribution.json`** (repo root) is the plugin-set + ordering authority. Per entry: the provider FQCN, the source kind modeled honestly — `folder` (plain in-repo folder on the root `"Plugins\"` PSR-4; Payments, no package/constraint fields — a folder entry declaring them is a validation error), `path` (in-repo composer package; Events), `vcs` (external repo; LogoGarden) — plus composer package name and bound constraint where one exists. Array order is the provider load order.
- **`config/plugins.php` is now a generated artifact:** new artisan command `plugins:manifest-sync` writes it from the manifest via the single reader `App\Plugins\DistributionManifest` (strict fail-loud validation naming the problem — the unknown-handle posture one level up; deterministic byte-stable output; generated-file header pointing editors at the manifest). The runtime loader still reads the plain PHP config list — no bootstrap-time JSON parsing; remove-the-entry ≡ remove-the-line by construction.
- **New standing guard `DistributionManifestGuardTest`** (4 tests): (a) regeneration idempotence — the committed config file is byte-identical to what the manifest generates, **verified to fail on a hand edit** during the session; (b) entry reality — providers autoload, source paths exist, composer.json presence matches the declared kind (a folder entry gaining a composer.json fails until the manifest re-declares it as `path`), package names match; (c) lock-pinning per declared source kind plus composer.json repository/require alignment (path → path repo + path dist; vcs → vcs repo + git source/zip dist; constraints match requires); (d) no unmanifested plugin surfaces — every `nonprofitcrm/*` lock package, every `plugins/` directory, every Dockerfile plugin-manifest COPY line (exactly one per path package per composer stage), and every `plugins/` phpunit testsuite traces to a manifest entry. `composer.json` and the Dockerfile stay hand-maintained per the session decision — the guard makes drift loud instead of building generation machinery.
- **Decision 3(d) resolved as replace-the-const:** `PluginPackageGuardTest`'s hand-maintained `EXTRACTED_PLUGIN_PACKAGES` list is gone; its extracted set now derives from the manifest's vcs-sourced entries, so an extraction is declared once, in the manifest.
