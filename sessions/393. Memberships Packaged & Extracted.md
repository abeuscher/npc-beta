## The redraw input (ground truth, captured from the dump at 392 close)

1. **Creation order:** `membership_tiers` → `memberships` (memberships.tier_id FK requires tiers first).
2. **`membership_tiers`:** uuid PK, `slug` unique, the `billing_interval` **check constraint** (monthly/annual/one_time/lifetime — raw-DDL fidelity matters here; schema-builder would risk expression-normalization drift). No outbound FKs, no inbound FKs from any core table.
3. **`memberships`:** uuid PK; **five outbound FKs** — `contact_id` → contacts **ON DELETE RESTRICT** (the only RESTRICT: blocks contact force-delete while memberships exist — the donation_receipts FK-as-behavior analogue; check whether a behavior net covers it and record the finding either way), `tier_id` → membership_tiers ON DELETE SET NULL (plugin-internal), `organization_id` → organizations SET NULL, `import_source_id` / `import_session_id` → import bookkeeping SET NULL. Four indexes (`contact_id`, the `import_source_id, external_id` composite, `organization_id`, `source`).
4. **No core table carries an FK into either table** (verified against the dump at 392 close) — the cleanest redraw of the three.
5. **No sequences** — both PKs are uuid; the first redraw with nothing in the sequences-travel-too category.
6. **Schema docs:** `docs/schema/memberships.md` + `docs/schema/membership_tiers.md` gain the plugin-ownership headers (the donations wording).
