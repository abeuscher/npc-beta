## What was built

### Phase 1 — C3c: comp-tier label + one-confirmation-per-order email timing

- **Comp-tier label** (display-only, behaviour stays price-driven): `ticket_tiers.is_complimentary` boolean (migration `2026_07_23_000001`), model fillable/cast, a `Toggle` in the `EventResource` ticket-tier repeater (dehydrates `null → false` — the repeater submits `null` for unfilled toggles), the field projected onto the EventRegistration widget contract (`SystemModelProjector::projectTiers`), and the public picker renders **"Complimentary"** for a comp-flagged $0 tier ("Free" stays for a plain $0 tier; priced tiers show the price regardless of flag).
- **Confirmation-email timing fix** — the thank-you now fires **once per order, at confirm time**. Dispatch relocated out of the per-row `EventRegistrationObserver::created` (which emailed at *every* row creation: paid rows at pending-creation before payment, multi-tier orders once per line) into the three confirm-points: `EventController::register` + `Portal\EventRegistrationController::store` (free path — one synchronous send after the create loop, via a `sendConfirmation()` helper) and `StripeWebhookController::handleEventRegistrationCheckout` (paid path — one **queued** send on the `pending → registered` promotion, mirroring the C3b acknowledgment pattern so a mail hiccup can't fail the webhook's 200). Replay-idempotent via the existing pending-only filter — a replayed webhook finds no pending rows and early-returns before the send; no new marker column needed. The observer keeps its other side-effects (sold-out flip, contact auto-create + `contact_id` linkage) untouched.
- **Create-path audit came back clean:** importers already suppress the observer wholesale (`withoutEvents()`, flag 344-C at session 345) and the admin panel can only view/delete registrations — so no path lost an email it needed. Mailing-list opt-in turned out to be a stored column consumed by `MailingListQueryBuilder`, not observer logic (session-prompt drift, noted) — unaffected by the relocation.
- **Free/comp skip-Stripe path locked in** with regression tests (pure-$0 order → no Stripe session, rows `registered`, exactly one email; mixed comp+paid order still routes to Stripe unchanged). The headline behaviour pre-existed (`EventRegistrationQuantities::isPaid()`) and was not rebuilt, per the session prompt.
- **Tests:** `RegistrationConfirmationTest` rewritten around the confirm-points (bare row creation sends nothing; tier-less free / multi-tier $0 / comp-only / portal free paths each send exactly one; webhook promotion queues exactly one incl. multi-row orders; replay sends none; contact auto-create still fires); `ImportEventRegistrationNoEmailTest`'s contrast case moved from a bare create to the controller flow; comp-label tests added to `TicketTierAdminRepeaterTest` (toggle persists) and `TicketTierPublicPickerTest` (projection, rendered labels via a real page GET, mixed-order routing unchanged).
- **Docs:** `docs/schema/ticket_tiers.md` column row; the stale `docs/app-reference.md` "Event checkout (POST) → EventCheckoutController" row replaced with the real `Portal\EventRegistrationController::store` row.

## Security considerations

The email relocation adds no new surface: the webhook send is queued (a mail failure cannot fail the webhook response, mirroring C3b) and inherits replay-idempotency from the pending-only promotion filter; the free-path sends occur inside already-validated, honeypot-guarded controller flows. The `nginx-certs/fm-client.crt` capture item was investigated as a suspected committed credential and proven a placeholder (public half only, no tracked private key, production cert provisioned host-side) — documented rather than rotated. The production recon surfaced that the S1 public CSP has been silently breaking Alpine on the public surface since deploy; the CSP itself is deliberately **unchanged** — the fix (session 375) migrates the front-end to comply with the policy, not the reverse.
